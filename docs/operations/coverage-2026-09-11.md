# Coverage-driven correctness and performance pass

Baseline: `1154f47b`, Rust 1.98.1 on macOS. Coverage identified agent backup
handling as the largest untested area. State-combination tests also exposed
defects in version metadata despite its already high line coverage.

## Fixes and regression evidence

- Agent and CLI bundle imports now check every referenced profile and secret
  against the requested project before applying rows. This includes profile
  keys, versions, and blobs. Tests proved that an import could previously alter
  another project's secret. Foreign and missing references now reject the
  transaction; tests verify that existing metadata, versions, and ciphertext
  remain unchanged and newly introduced profiles do not persist.
- Accepting a local secret also retains its versions and blobs. Previously,
  importing a missing incoming current version could deprecate the retained
  local version, leaving the secret pointer aimed at an unusable version.
  The conflict matrix tests cover local, incoming, and review choices, including
  unrelated new secrets and complete rollback when review is required.
- Import rotation expires the previous local version after processing all
  incoming version rows. Historical rows cannot restore the exporter's grace
  window. Repeated imports also preserve locally expired deadlines, including
  an absent deadline. Tests cover both historical-row orders and repeated
  imports. These failures reproduced in both the agent and CLI before fixing.
- Version lists distinguish pinned-reference eligibility from scan inclusion.
  Deleted versions cannot resolve, but deleted current versions and historical
  versions still within grace remain eligible for leak detection. Tests verify
  these combinations, exact expiry, filtering, and project/profile isolation.
- Scanner candidate columns now advance during token segmentation. The previous
  implementation rescanned the preceding text for every detected candidate,
  making dense delimiter-separated lines quadratic. Tests retain exact Unicode
  columns, newline/control handling, finding counts, and redacted output.

Additional coverage checks actual profile-key rewrapping under the receiver's
master key, rejection with a wrong key, and idempotent repeated imports.
Independent review identified the repeated-import grace case and found no
remaining blocking issue after that correction.

## Dense-line benchmark

The fixture repeats `é=ghp_example,` on one line. Every measured call checks
finding count, kind, length, and Unicode column positions. Both binaries use
the same release toolchain. The baseline binary was preserved before the
scanner change. Three alternating runs per binary each report the median of
seven calls; the table gives the median of those three results.

| Findings | Bytes | Before | After |
| ---: | ---: | ---: | ---: |
| 1,000 | 15,000 | 0.588 ms | 0.095 ms |
| 5,000 | 75,000 | 13.241 ms | 0.478 ms |
| 10,000 | 150,000 | 165.447 ms | 1.187 ms |

Timing varied, particularly in the largest baseline fixture: its three run
medians ranged from 96 to 227 ms, versus 1.13 to 1.59 ms after the change.
These measurements apply to dense lines, not overall application latency.
The existing normal-line and repetitive-known-secret redaction benchmarks
also passed their output assertions.

## Verification and reproduction

All 1,371 instrumented Rust tests passed across 19 test targets. Strict
workspace Clippy, formatting, and documentation checks passed. The existing
`proc-macro-error2` future-compatibility notice remains.

```sh
export CARGO_TARGET_DIR=/Volumes/Scratch/locket/coverage-target
export TMPDIR=/Volumes/Scratch/locket/tmp
export RUSTC_WRAPPER=/opt/homebrew/bin/sccache
export CARGO_INCREMENTAL=0
cargo llvm-cov --workspace --all-features --locked --json \
  --output-path /Volumes/Scratch/locket/reports/coverage-final.json
cargo llvm-cov report --html \
  --output-dir /Volumes/Scratch/locket/reports/coverage-html

CARGO_TARGET_DIR=/Volumes/Scratch/locket/target \
  cargo run -p locket-scan --example dense_scan_bench --release --locked
```

The machine-specific paths above keep build and report data on Scratch. JSON
baselines, final coverage, failing/passing regression logs, and
`dense-scan-comparison.json` are in `/Volumes/Scratch/locket/reports`.
The browsable report is `coverage-html/html/index.html` within that directory.
